# Referência Técnica — ESP32 CYD 2432S028 + ST7789

**Board:** ESP32 CYD 2432S028 ("Cheap Yellow Display")
**Chip:** Espressif ESP32-WROOM-32
**Driver de tela:** ST7789
**Driver de touch:** XPT2046 / TPM408

---

## Display ST7789

### Pinagem (barramento HSPI)

| Sinal | GPIO | Notas |
|-------|------|-------|
| MISO  | 12   | SDO (não obrigatório para escrita apenas) |
| MOSI  | 13   | SDI — dados para o display |
| CLK   | 14   | Clock SPI |
| CS    | 15   | Chip Select (ativo LOW) |
| DC    | 2    | Data/Command select |
| RST   | -1   | Não conectado (reset via software ou VCC) |
| BL    | 21   | Backlight — OUTPUT, HIGH = ligado |

### Inicialização obrigatória

```cpp
SPIClass hspi(HSPI);
Adafruit_ST7789 tft = Adafruit_ST7789(&hspi, TFT_CS, TFT_DC, TFT_RST);

hspi.begin(TFT_CLK, TFT_MISO, TFT_MOSI, TFT_CS);
tft.init(240, 320);         // ATENÇÃO: parâmetros são (largura, altura) antes da rotação
tft.invertDisplay(true);    // OBRIGATÓRIO neste modelo — corrige inversão de cores do ST7789
tft.setRotation(3);         // Landscape 320×240 (rotação 3 = landscape invertido)
tft.fillScreen(0x0000);     // Limpa tela

// Backlight
pinMode(TFT_BL, OUTPUT);
digitalWrite(TFT_BL, HIGH);
```

> **Por que `invertDisplay(true)`?** Este modelo específico (2432S028) tem a polaridade das cores invertida no hardware. Sem isso, as cores ficam complementares (preto→branco, vermelho→ciano, etc.).

> **Por que `tft.init(240, 320)` e não `(320, 240)`?** A biblioteca Adafruit_ST7789 recebe dimensões nativas do painel (antes da rotação). O painel físico é 240 wide × 320 tall. A rotação 3 transpõe para 320×240.

### Dimensões úteis (após `setRotation(3)`)

| Constante | Valor |
|-----------|-------|
| SCREEN_W  | 320   |
| SCREEN_H  | 240   |

### Rotações disponíveis

| Valor | Orientação |
|-------|-----------|
| 0     | Portrait normal (240×320) |
| 1     | Landscape (320×240) |
| 2     | Portrait invertido (240×320) |
| 3     | Landscape invertido (320×240) ← **usado neste projeto** |

### Biblioteca

```cpp
#include <SPI.h>
#include <Adafruit_GFX.h>
#include <Adafruit_ST7789.h>
```

## Touch XPT2046 / TPM408

### Pinagem (barramento VSPI — dedicado, separado do display)

| Sinal | GPIO | Notas |
|-------|------|-------|
| MOSI  | 32   | SDI do controlador de touch |
| MISO  | 39   | SDO do controlador (INPUT ONLY no ESP32) |
| CLK   | 25   | Clock SPI |
| CS    | 33   | Chip Select (ativo LOW) |
| IRQ   | 36   | Interrupt — LOW quando tela tocada (INPUT ONLY no ESP32) |

> **GPIOs 34, 35, 36, 39** no ESP32 são **somente leitura** (input-only). Por isso TOUCH_MISO (39) e TOUCH_IRQ (36) não podem ter `pinMode(xx, OUTPUT)`.

### Inicialização

```cpp
SPIClass vspi(VSPI);

vspi.begin(TOUCH_CLK, TOUCH_MISO, TOUCH_MOSI, TOUCH_CS);
pinMode(TOUCH_CS, OUTPUT);
digitalWrite(TOUCH_CS, HIGH);   // desativa o chip por padrão
pinMode(TOUCH_IRQ, INPUT);      // IRQ: sem pull — o hardware já tem pull-up
```

### Leitura de toque (padrão aprovado)

```cpp
uint16_t touchReadRaw(uint8_t cmd) {
  vspi.transfer(cmd);
  uint16_t val = (vspi.transfer(0) << 8) | vspi.transfer(0);
  return val >> 3;   // resultado 12-bit
}

bool readTouch(int16_t &tx, int16_t &ty) {
  if (digitalRead(TOUCH_IRQ) == HIGH) return false;   // IRQ ativo LOW

  vspi.beginTransaction(SPISettings(1000000, MSBFIRST, SPI_MODE0));
  digitalWrite(TOUCH_CS, LOW);

  // 8 amostras para filtrar ruído
  const int SAMPLES = 8;
  long rawA[SAMPLES], rawB[SAMPLES];
  for (int i = 0; i < SAMPLES; i++) {
    rawA[i] = touchReadRaw(0x90);   // canal Y do chip = eixo X na tela (landscape)
    rawB[i] = touchReadRaw(0xD0);   // canal X do chip = eixo Y na tela (landscape)
  }

  digitalWrite(TOUCH_CS, HIGH);
  vspi.endTransaction();

  if (digitalRead(TOUCH_IRQ) == HIGH) return false;   // dedo levantou durante leitura

  // Insertion sort + descarta 2 outliers de cada lado, média dos 4 centrais
  for (int i = 1; i < SAMPLES; i++) {
    for (int j = i; j > 0 && rawA[j] < rawA[j-1]; j--) { long t=rawA[j]; rawA[j]=rawA[j-1]; rawA[j-1]=t; }
    for (int j = i; j > 0 && rawB[j] < rawB[j-1]; j--) { long t=rawB[j]; rawB[j]=rawB[j-1]; rawB[j-1]=t; }
  }
  long sumA = 0, sumB = 0;
  for (int i = 2; i < SAMPLES - 2; i++) { sumA += rawA[i]; sumB += rawB[i]; }
  uint16_t xRaw = sumA / (SAMPLES - 4);
  uint16_t yRaw = sumB / (SAMPLES - 4);

  // Rejeita leituras fora da faixa válida
  if (xRaw < 200 || xRaw > 3900 || yRaw < 200 || yRaw > 3900) return false;

  // Mapeamento calibrado para setRotation(3) — ambos os eixos normais
  tx = map(xRaw, 300, 3750, 0, SCREEN_W);
  ty = map(yRaw, 300, 3750, 0, SCREEN_H);
  tx = constrain(tx, 0, SCREEN_W - 1);
  ty = constrain(ty, 0, SCREEN_H - 1);

  return true;
}
```

### Parâmetros do controlador de touch

| Parâmetro | Valor |
|-----------|-------|
| Velocidade SPI | 1 MHz |
| Bit order | MSBFIRST |
| Modo SPI | SPI_MODE0 |
| Resolução ADC | 12 bits (val >> 3 do dado de 15 bits) |
| Comando canal Y (→ X na tela) | `0x90` |
| Comando canal X (→ Y na tela) | `0xD0` |
| IRQ | Ativo LOW |
| Faixa raw válida | 200 – 3900 |
| Faixa de calibração (este modelo) | 300 – 3750 |

### Detecção de tap com debounce

```cpp
bool detectTap(int16_t &tx, int16_t &ty) {
  bool pressed = readTouch(tx, ty);
  unsigned long now = millis();
  if (pressed && !lastTouchState && (now - lastTouchTime > 300)) {
    lastTouchState = true;
    lastTouchTime  = now;
    return true;
  }
  if (!pressed) lastTouchState = false;
  return false;
}
```

## Barramentos SPI — Resumo

| Barramento | Uso | GPIOs |
|-----------|-----|-------|
| HSPI | Display ST7789 | CLK=14, MISO=12, MOSI=13, CS=15 |
| VSPI | Touch XPT2046 | CLK=25, MISO=39, MOSI=32, CS=33 |

> Os dois barramentos são **completamente independentes** — podem operar em paralelo sem conflito.

## Notas de Hardware Importantes

1. **GPIOs 34, 35, 36, 39** são input-only — nunca usar como OUTPUT
2. **GPIO 0** — boot mode pin; cuidado ao usar em projetos
3. **GPIO 2** — usado como TFT_DC; também é o LED onboard (pode piscar na inicialização)
4. `TFT_RST = -1` significa que o reset do display está conectado diretamente ao VCC (3.3V) ou ao pino de reset do ESP32, sem controle por GPIO
5. O display e o touch **não compartilham CS** — cada um tem seu próprio Chip Select
6. A tela precisa de `invertDisplay(true)` — sem isso as cores ficam invertidas
7. Sempre iniciar o SPI com `hspi.begin(CLK, MISO, MOSI, CS)` antes de `tft.init()`
